実装できる ≠ 決めてよい

Forge は「どう実装するか」を決めるのではなく、実装前に「AI が決めてよいこと」と「人が決めるべきこと」を分けます。

6つの段階で分解する。

Illustrative Scenario
考え方を示すための簡略化した業務シナリオです。実在するリポジトリでの実行結果ではありません。

STEP 01入力

要件

注文詳細画面から、注文をキャンセルできるようにしたい。

この要件が触れる実装面をたどり、根拠と未確定の判断を段階ごとに整理します。

入力requirement.order_cancellation

判断の境界

技術的に妥当でも、
承認された判断とは限らない。

WITHOUT / 01 技術的に妥当な仮定

Coding Agent が補うかもしれない前提

  • PAID→CANCELLED
  • 自動で返金を実行する
  • 在庫を即時に戻す
  • 顧客本人ならキャンセル可能

いずれも技術的には自然な選択肢です。しかし、要件や Project Context によって許可された判断とは限りません。

WITH / 02 判断権限で分離

Forge が確認するのは、Project Context から安全に確定できない判断だけです。

03 観測済み ✓ 質問せず、実装 Context へ
  • Payment.refund() が存在する
  • 在庫予約が存在する
  • 注文 status の変更は Audit Log 対象
03 人の判断が必要 ! ここだけ Human Alignment へ
  • 返金ポリシー
  • キャンセル権限
  • 在庫を解放するタイミング
Forge の分離原則

すべてを質問するのではなく、確立できる事実は引き継ぎ、推論してはいけない判断だけを人に戻します。
